# 🖥️ 아두이노 강의 index.md ➡️ slides.md 변환 공식 가이드

본 가이드는 아두이노 피지컬 컴퓨팅 & IoT 마스터 코스의 **상세 교재 문서(`index.md`)**를 교육용 프리젠테이션 및 발표용 **슬라이드 문서(`slides.md`)**로 일관되고 완성도 높게 변환하기 위한 공식 제작 표준 지침서입니다.

강사와 학습자 모두가 발표 현장과 자습 환경에서 최고의 시각적 효과와 몰입도를 경험할 수 있도록, 슬라이드 구조 설계부터 시각 자료 매핑, 구어체 강의 대본 작성, 그리고 품질 무결점 검증까지 전 과정을 표준화합니다.

## 1. 핵심 설계 원칙 (Core Principles)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        3대 불변의 품질 원칙                             │
│                                                                        │
│ 1. 1 슬라이드 1 핵심 주제 (One Idea per Slide)                          │
│    - 한 화면에 텍스트를 빽빽하게 넣지 않고 불릿 3~5개 이내로 정돈        │
│                                                                        │
│ 2. 전 슬라이드 구어체 대본 수록 (100% Spoken Script)                   │
│    - 모든 슬라이드 하단에 친절한 강의 멘트(`> `) 필수 수록             │
│                                                                        │
│ 3. 단원 내 이미지 중복 0% (Zero Duplicates Policy)                     │
│    - 한 단원(`slides.md`) 안에서 동일한 이미지를 중복 사용 금지        │
│    - 슬라이드별 교육 주제에 1:1로 부합하는 고유 칠판 일러스트 매핑     │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. 슬라이드 표준 규격 및 마크다운 문법

### 📏 기본 레이아웃 규격
* **슬라이드 화면 비율**: `16:9` 와이드스크린 기준
* **슬라이드 구분자**: 독립된 단일 행의 `---` 사용 (`(?m)^---\s*$`)
* **타이틀 계층**:
  * 표지 슬라이드: `# 단원번호_단원명 [이모지]` (H1)
  * 본문 슬라이드: `## n. 주요주제 [이모지]` (H2)
  * 세부 슬라이드: `### 세부주제 [이모지]` (H3)
* **이미지 문법**: `![대체텍스트](./img/파일명.jpg)`
* **강의 대본 문법**: 마크다운 인용구 블록 `> 강의 멘트`

## 3. 슬라이드 유형별 상세 템플릿

각 단원은 학습 흐름에 따라 다음 5가지 유형의 슬라이드로 유기적으로 구성됩니다.

### 🌟 Type 1: 표지 슬라이드 (Title Cover Slide)
단원의 도입부로, 학습 목표와 등장인물 대화, 교재 상호 링크가 포함됩니다.

```markdown
# 040_부저란_마법의소리떨림판 🎵🔊
### 도로시와 지니가 함께하는 피에조 부저의 소리 발생 원리와 진동판의 비밀

![피에조 부저를 탐구하는 도로시와 지니](./img/dorothy_buzzer_intro.jpg)

* **오늘의 미션**: 전기를 소리로 바꾸는 마법의 떨림판, 부저(Buzzer)의 내부 구조를 파헤쳐요!
* **선생님**: 마법 멘토 지니 & 호기심 탐험가 도로시 & 토토
* 📖 **상세 강의 교재**: [index.md](./index.md)

> 여러분 안녕하세요! 이번 시간에는 '040. 부저란 마법의 소리 떨림판 🎵🔊'을 주제로 신기한 소리 탐험을 떠나보겠습니다. 화면을 보시면 도로시와 지니가 책상 위에서 작고 동그란 부품을 들여다보고 있지요? 전기가 통하면 어떻게 '삐~' 하는 맑은 소리가 나는지, 피에조 소자의 놀라운 떨림 원리를 지금부터 알기 쉽게 설명해 드리겠습니다. 준비되셨나요? 힘차게 출발해 봅시다!
```

### 🔬 Type 2: 원리 및 개념 슬라이드 (Theory & Concept Slide)
핵심 동작 원리를 일러스트와 요약 포인트로 전달합니다.

```markdown
## 1. 피에조 부저의 내부 구조와 압전 효과

![피에조 압전 소자의 수축과 팽창 원리](./img/dorothy_piezo_element_structure.jpg)

* **피에조 효과 (압전 현상)**: 특정 결정체에 전압을 가하면 모양이 늘어나거나 줄어드는 물리적 현상
* **세라믹 진동판**: 얇은 금속판 위에 세라믹 압전 물질이 코팅되어 있어 전압에 따라 위아래로 진동
* **공기 파동 생성**: 진동판이 1초에 수백~수천 번 떨리며 공기를 밀어내어 우리 귀에 들리는 음파(소리) 형성

> 화면의 다이어그램을 주목해 주시기 바랍니다. 부저 내부에는 아주 얇은 원형 금속판과 세라믹 압전 소자가 붙어 있습니다. 여기에 전압을 가하면 물질이 찰나의 순간에 팽창했다가 수축하면서 진동판을 위아래로 힘차게 흔들게 됩니다. 이때 주변 공기가 파동을 일으키며 우리 귀에 소리로 들리게 되는 것이죠. 마치 스피커의 떨림판이 공기를 치는 것과 완전히 같은 원리랍니다.
```

### 🔌 Type 3: 회로 연결 및 핀맵 슬라이드 (Wiring & Circuit Slide)
부품 핀맵과 브레드보드 결선도를 보여주는 슬라이드입니다.

```markdown
## 2. 능동 부저 vs 수동 부저 구별법과 극성 연결

![부저의 밑면 극성 스티커와 핀 길이 비교](./img/dorothy_active_vs_passive_buzzer.jpg)

* **긴 다리 (+ / 아노드)**: 아두이노 디지털 핀(예: D8) 또는 5V에 연결
* **짧은 다리 (- / 캐소드)**: 아두이노 접지(GND)에 직결
* **보호 스티커 확인**: 능동 부저는 상단에 방수/보호용 스티커가 붙어 있고 바닥이 검은색 에폭시로 밀봉됨

> 이번에는 부저의 극성과 올바른 회로 연결법을 살펴보겠습니다. LED처럼 부저도 다리 길이가 서로 다릅니다. 긴 다리가 플러스(+), 짧은 다리가 마이너스(-)입니다. 반대로 꽂으면 소리가 나지 않거나 부품에 무리가 갈 수 있으니, 긴 다리를 아두이노 디지털 신호 핀에, 짧은 다리를 반드시 GND에 꽂아주어야 한다는 점을 꼭 기억해 두세요!
```

### 💻 Type 4: 실전 소스코드 분석 슬라이드 (Code Walkthrough Slide)
핵심 스케치 코드를 30줄 이내로 제시하고 동작 흐름을 설명합니다.

```markdown
## 3. 디지털 핀을 이용한 비프음 발생 기본 스케치

![부저 비프음 제어 코드 칠판 설명](./img/dorothy_buzzer_beep_sketch.jpg)

```cpp
const int buzzerPin = 8;

void setup() {
  pinMode(buzzerPin, OUTPUT);
}

void loop() {
  digitalWrite(buzzerPin, HIGH); // 소리 켜기
  delay(500);                     // 0.5초 유지
  digitalWrite(buzzerPin, LOW);  // 소리 끄기
  delay(500);                     // 0.5초 대기
}
```

> 화면에 제시된 아두이노 C++ 코드를 함께 분석해 보겠습니다. setup() 함수에서 8번 핀을 OUTPUT(출력 모드)으로 설정한 뒤, loop() 안에서 digitalWrite를 통해 5V 전압을 넣었다가 0V로 끊어주는 과정을 0.5초 간격으로 반복하고 있습니다. 능동 부저를 사용하면 이 간단한 코드만으로도 '삐- 삐- 삐-' 하는 규칙적인 전자 비프음을 손쉽게 만들어낼 수 있습니다.
```

### 🏆 Type 5: 학습 정리 및 요약 슬라이드 (Wrap-up Slide)
단원의 핵심 내용을 총정리하고 성취감을 북돋우는 마무리 슬라이드입니다.

```markdown
## 🌟 도로시와 지니의 핵심 요약 노트! 🏆

![완성된 부저 회로를 들고 기뻐하는 도로시와 지니](./img/dorothy_jiny_celebrate.jpg)

* 🔔 **압전 소자의 마법**: 전기를 물리적 진동으로 바꾸어 공기 파동을 일으킨다!
* ⚡ **극성 주의**: 긴 다리는 신호 핀(+), 짧은 다리는 접지(GND)에 연결한다!
* 🎵 **수동 vs 능동**: 자체 발진 회로 유무에 따라 멜로디 연주 가능 여부가 달라진다!

> 여러분, 오늘 배운 핵심 내용이 머릿속에 쏙쏙 정리되셨나요? 전기가 소리로 바뀌는 피에조 효과의 원리부터 능동 부저를 코드로 제어하는 방법까지 완벽하게 정복했습니다! 오늘 실습한 내용을 토대로 다음 시간에는 다양한 주파수를 넣어 도레미파솔라시도 음악을 직접 연주하는 '수동 부저 멜로디 제어'에 도전해 보겠습니다. 수고 많으셨습니다!
```

## 4. 단계별 변환 워크플로우 (Step-by-Step)

```
 [index.md 교재 원문 분석]
         │
         ▼
 [1. 섹션 헤딩 파악 (##, ###)] ──▶ 내용 분량에 따라 1~2개 슬라이드로 분할
         │
         ▼
 [2. 텍스트 불릿 포인트 요약]  ──▶ 장문 서술형 문장을 3~5개 핵심 불릿으로 압축
         │
         ▼
 [3. 슬라이드별 고유 이미지 배정] ─▶ 단원 내 중복 0% 검증 & 16:9 일러스트 매핑
         │
         ▼
 [4. 구어체 강의 대본 작성 (`>`)]  ─▶ 슬라이드 시각 요소와 코드를 짚어주는 멘트 생성
         │
         ▼
 [5. 양방향 링크 상호 삽입]     ─▶ index.md ↔ slides.md 원터치 이동 링크 구축
         │
         ▼
 [6. 최종 무결점 스크립트 검증]   ─▶ 분할 오류, 스크립트 누락, 이미지 중복 0건 확인
```

## 5. 구어체 강의 스크립트(`>`) 작성 규칙

모든 슬라이드의 맨 마지막 줄에는 반드시 `> `로 시작하는 강의 대본을 작성해야 합니다.

### ✍️ 작성 원칙
1. **자연스러운 구어체 존댓말**: 
   - ❌ "피에조 부저는 전압에 반응함." (문어체 금지)
   - ⭕ "화면을 보시면 피에조 부저가 전압의 변화에 따라 미세하게 떨리는 모습을 확인할 수 있습니다."
2. **시각 자료 능동적 지칭**:
   - 강사가 레이저 포인터로 칠판을 짚어주듯, "왼쪽 다이어그램의 파란색 선을 보세요", "코드 12행의 delay 함수를 주목해 주세요"와 같이 화면 요소를 가리켜야 합니다.
3. **등장인물 페르소나 자연스러운 반영**:
   - 도로시의 질문("도로시가 방금 질문했듯이..."), 지니의 마법 비유("지니의 마법처럼 전자의 흐름을 상상해 보세요")를 가미하여 생동감을 부여합니다.
4. **천편일률적인 복붙 템플릿 금지**:
   - 코드가 없는 개념 슬라이드에 "화면의 코드를 살펴보시면..."이라고 말하는 템플릿 불일치 오류를 엄격히 금지합니다.

## 6. 이미지 배치 및 단원 내 중복 0% 원칙

### 🚫 제로 듀플리케이트 (Zero Duplicate Policy)
* **금지 사항**: 같은 `slides.md` 파일 안에서 동일한 이미지 파일명이 2회 이상 등장해서는 안 됩니다.
* **표지 및 요약 이미지 분리**:
  * 표지 슬라이드: 단원 주제별 전용 커버 일러스트 (`dorothy_..._intro.jpg` 등)
  * 마무리 슬라이드: 축하/완성 일러스트 (`dorothy_jiny_celebrate.jpg`)
* **본문 슬라이드 일러스트 매핑**:
  * 반드시 `guides/character.md` [버전 2] 2D 치비 화이트보드/칠판 스타일 가이드를 준수하는 고유 이미지를 슬라이드 주제와 1:1로 매칭합니다.

## 7. 상호 연동 링크 규격 (`index.md` ↔ `slides.md`)

학습자와 강사가 교재와 슬라이드 사이를 자유롭게 넘나들 수 있도록 양방향 원터치 링크를 표준 위치에 배치합니다.

### 📍 `index.md` 측 배치 규칙
문서 도입부 메타데이터 목록의 마지막 줄, 첫 번째 `---` 바로 위에 삽입합니다.

```markdown
* **오늘의 탐험**: 에너지는 무엇이고, 어떻게 빛과 소리로 변신할까?
* **선생님**: 마법 멘토 지니 & 호기심 탐험가 도로시 & 토토
* 🖥️ **강의 슬라이드**: [slides.md](./slides.md)

---
```

### 📍 `slides.md` 측 배치 규칙
첫 번째 슬라이드(표지) 메타데이터 목록의 마지막 줄에 삽입합니다.

```markdown
* **오늘의 탐험**: 에너지는 무엇이고, 어떻게 빛과 소리로 변신할까?
* **선생님**: 마법 멘토 지니 & 호기심 탐험가 도로시 & 토토
* 📖 **상세 강의 교재**: [index.md](./index.md)

> 여러분 안녕하세요! ...
---
```

## 8. 자주 발생하는 오류 및 예방 팁 (Troubleshooting)

### ⚠️ Gotcha 1: 마크다운 표(Table) 내부 구분자와 슬라이드 구분자 혼동
* **문제 현상**: 마크다운 테이블 행인 `| :--- | :--- |`을 파이썬의 단순 문자열 `split("---")`으로 쪼개면, 표가 산산조각 나면서 수십 개의 빈 슬라이드가 생성됩니다.
* **해결책**: 반드시 **정규표현식 행 단위 구분자** `(?m)^---\s*$`를 사용하여 독립된 줄의 `---`만 슬라이드 전환선으로 인식해야 합니다.

### ⚠️ Gotcha 2: ASCII 박스 아트 및 코드 블록 내 구분자
* **문제 현상**: `+-------------------+` 같은 ASCII 다이어그램 내부의 연속 대시(`---`)가 슬라이드로 쪼개지는 현상.
* **해결책**: 슬라이드 분할 시 코드 블록(```) 내부는 분할 대상에서 제외하거나, 분할 정규식을 줄 시작과 끝(`^---$`)으로 엄격히 한정합니다.

### ⚠️ Gotcha 3: 상대 경로 깨짐
* **문제 현상**: `slides.md`에서 이미지를 참조할 때 `img/photo.png` 또는 `../img/photo.png`로 잘못 적어 이미지가 엑박이 뜨는 문제.
* **해결책**: 언제나 해당 챕터 기준 `./img/파일명.jpg` 상대 경로를 준수합니다.

## 9. 품질 검증 자동화 스크립트 (QA Checklist)

새로운 단원을 변환하거나 기존 단원을 수정한 후, 다음 파이썬 스크립트를 실행하여 100% 무결점을 자동으로 검증합니다.

```python
import os, glob, re
from collections import Counter

def audit_slides(base_path):
    slides_files = sorted(glob.glob(f"{base_path}/Part*/*/slides.md"))
    print(f"🔍 총 점검 대상 slides.md: {len(slides_files)}개")

    total_slides = 0
    missing_scripts = []
    duplicate_images = []
    broken_images = []

    for sf in slides_files:
        ch_dir = os.path.dirname(sf)
        ch_name = os.path.basename(ch_dir)

        with open(sf, "r", encoding="utf-8") as f:
            content = f.read()

        # 1. 올바른 행 단위 슬라이드 분할
        slides = re.split(r"(?m)^---\s*$", content)
        
        for i, s in enumerate(slides):
            if not s.strip():
                continue
            total_slides += 1

            # 2. 강의 스크립트(>) 누락 검사
            if not re.search(r"^\s*>\s*.+", s, re.MULTILINE):
                missing_scripts.append((ch_name, i + 1))

        # 3. 단원 내 이미지 중복 검사
        imgs = re.findall(r"!\[.*?\]\((.*?)\)", content)
        counts = Counter(imgs)
        dupes = {img: cnt for img, cnt in counts.items() if cnt > 1}
        if dupes:
            duplicate_images.append((ch_name, dupes))

        # 4. 이미지 파일 실제 존재 여부 검사
        for img in imgs:
            img_path = os.path.normpath(os.path.join(ch_dir, img))
            if not os.path.exists(img_path):
                broken_images.append((ch_name, img))

    print("\n" + "="*50)
    print(f"📊 총 유효 슬라이드 수: {total_slides}장")
    print(f"❌ 대본 누락 슬라이드: {len(missing_scripts)}개")
    print(f"❌ 단원 내 이미지 중복: {len(duplicate_images)}개 단원")
    print(f"❌ 깨진 이미지 링크: {len(broken_images)}개")
    print("="*50)

    if not missing_scripts and not duplicate_images and not broken_images:
        print("🎉 축하합니다! 모든 슬라이드가 100% 무결점 표준을 충족합니다!")
    else:
        print("⚠️ 발견된 오류 내역을 확인하고 수정해 주세요.")

if __name__ == "__main__":
    audit_slides("/Users/hojin9/Library/CloudStorage/OneDrive-개인/070.강의/아두이노2_ppt_ai")
